Traditional Extractors (WinRAR / 7-Zip)

Unpacks everything first, requiring 2× disk space before you can delete the archive.

50 GB archive + 50 GB extracted = 100 GB needed → Fails on 55 GB free

ZeroExtract (In-Place Space Recycling)

Punches sparse holes & truncates completed bytes in lockstep so peak usage stays near 1×.

50 GB archive → ~50 GB peak disk footprint → Succeeds on 55 GB free

Built for Massive Archives & Safety

Verify first, extract atomically, and recover cleanly from interruptions.

🛡

0-Byte Preflight Shield

Checks headers, central directories, CRCs, and passwords in memory before modifying a single byte on disk.

✂

Reverse Truncation + Sparse Holes

Uses Win32 FSCTL_SET_ZERO_DATA on NTFS and fallocate(FALLOC_FL_PUNCH_HOLE) on Linux.

📦

ZIP, RAR, 7z & Split Volumes

Supports .zip, .zip64, .rar, .7z, and progressively unlinks .z01 / .part1.rar / .001 parts.

🔒

Password-Protected Archives

Supports --password in CLI and a secure prompt in the GUI for encrypted ZIP, RAR, and 7z files.

⏸

Pause & Crash-Safe Resume

Tracks progress in .unpack_journal.json and stages files atomically via .unpack_part.

🖥

Desktop GUI & CLI

Includes drag-and-drop GUI, live Peak Space Saved counter, dry-run mode, and Windows Explorer context menu.

Out of Disk Space?

If Even the Extracted Files Won't Fit

ZeroExtract eliminates the 2× extraction spike, but your drive still needs room for the final unpacked files. If you are permanently out of space, consider offloading old archives to encrypted cloud storage or upgrading to a secondary NVMe SSD.

Tip: Run zeroextract --dry-run your_archive.zip first to see the exact final unpacked size before extracting.
